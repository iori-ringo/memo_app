# レンダリング効率改善プラン — 不要再レンダリング排除

## 概要

React Profiler 計測（NO3レポート）で特定された不要再レンダリングを排除し、テキストブロック操作時のコミット時間を 38.7ms → 16ms以下（60fps達成）に改善する。

## 背景・動機

- テキストブロックの作成・リサイズ・ドラッグ操作で **324コミット**、最大 **38.7ms/コミット** を記録
- 12回のレンダリング中 **10回が16.67ms（60fps目標）を超過** → インタラクション中にジャンクが発生
- キャンバス操作と無関係なサイドバー（4.8ms）、ツールバー（4.5ms）が毎回再レンダリングされている
- `React.memo` を適用済みの `PageListItem`, `ConnectionLayer` も props の参照不安定により無効化

**関連プラン**: `20260314-パフォーマンス最適化-ReactProfiler-Lighthouse.md` の Phase 2〜3 に該当。本プランは計測結果に基づく具体的な実装タスクに特化。

## 技術スタック

- Next.js (App Router) / React 19 / TypeScript
- Zustand（状態管理） / TipTap v3（リッチテキスト）
- react-draggable / react-resizable

## 実装方針

4段階で進め、各段階の完了後に React Profiler で再計測し効果を確認する。

```
Step 1: ストアセレクタの粒度細分化（サイドバー不要レンダリング排除）
  ↓  再計測
Step 2: ツールバーの Memo 化（ツールバー不要レンダリング排除）
  ↓  再計測
Step 3: Memo 無効化コンポーネントの修正（props 安定化）
  ↓  再計測
Step 4: HomeContent のコンポーネント分割（完全な独立レンダリング）
  ↓  最終計測・レポート
```

**原則**: 変更は最小限に。既存の動作を壊さないよう、各ステップでアプリの動作確認を行う。

## タスク分解

### Step 1: ストアセレクタの粒度細分化（推定効果: -4.8ms）

**問題**: `useNotes()` が `pages` 配列全体を購読 → オブジェクト座標変更でもサイドバーが再レンダリング

- [x] `note-store.ts` に `selectActivePage` セレクタを追加 <!-- completed: 2026-03-14 -->
  - `(s) => s.pages.find(p => p.id === s.activePageId && !p.deletedAt)`
  - キャンバスはこのセレクタでアクティブページのみ購読
- [x] `note-store.ts` に `selectPagesMeta` セレクタを追加 <!-- completed: 2026-03-14 -->
  - `pages` から `objects` / `connections` を除外したメタデータ配列を返す
  - 構造的共有で参照安定化 + `pagesMetaEqual` でカスタム等価比較
  - `zustand/traditional` の `useStoreWithEqualityFn` で購読
- [x] `use-sidebar-notes.ts` を新規作成（サイドバー専用フック） <!-- completed: 2026-03-14 -->
- [x] `home-content.tsx` から `useNotes()` / `useTrash()` を除去し `selectActivePage` で直接購読 <!-- completed: 2026-03-14 -->
- [ ] 再計測: サイドバーコンポーネントがキャンバス操作で再レンダリングされないことを確認

### Step 2: ツールバーの Memo 化（推定効果: -4.5ms）

**問題**: `RibbonToolbar` が `React.memo` なし → 親の再レンダリングが全ボタンに伝播

- [x] `ribbon-toolbar.tsx` を `React.memo` でラップ <!-- completed: 2026-03-14 -->
- [x] `notebook-canvas.tsx` で `RibbonToolbar` に渡す props を安定化 <!-- completed: 2026-03-14 -->
  - `hasSelection` は `useMemo` で安定化
  - `onDelete` (`handleDeleteSelection`) は既に `useCallback` → OK
  - `onToggleConnectMode` は既に `useCallback` → OK
  - `editor` は `activeEditor` state → 選択変更時のみ変化 → OK
  - `isConnectMode` は state → モード切替時のみ変化 → OK
- [x] 子コンポーネントの Memo 化は **不要**（親が Memo で止まるため） <!-- confirmed: 2026-03-14 -->

## 懸念点・検討事項

- **`selectPagesMeta` の shallow equality**: Zustand の `shallow` はオブジェクト配列の浅い比較なので、`pages.map(...)` で毎回新配列を作ると機能しない。カスタム equality 関数または `JSON.stringify` ベースの比較が必要
- **`useCanvasOperations` の ref パターン導入リスク**: `page.objects` を ref に入れると、古い値を参照するクロージャバグのリスクがある。`useRef` + `useEffect` で最新値を同期する useLatest パターンで安全に実装する
- **Step 4 のコンポーネント分割**: `MotionPageWrapper` へのアニメーション（ページ切替時）との統合に注意。`activePageId` の変更がアニメーションのトリガーになっている
- **Electron IPC との相互作用**: ストアの `subscribe` による自動保存（300ms debounce）は今回の変更では触らない。セレクタ変更がsubscribe の挙動に影響しないことを確認する
- **計測環境の統一**: 再計測は同一条件（CPU 4x slowdown、同一データセット、同一操作手順）で行うこと
